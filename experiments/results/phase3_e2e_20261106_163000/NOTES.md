# Phase 3 端到端實測（GPU，2026-11-06）

環境：ComfyUI 0.36.0 @ 127.0.0.1:8190、RTX 5080；後端 uvicorn port 8010，暫用 storage（不是正式 storage/app.db）。
流程以 API 腳本執行（A4 印刷廠繪本 → 角色 → 一頁 → 選圖 → 線稿 → QA → 自動補線 → 修一筆 → 角色一致 → 通過 → 匯出 → 改 A5）。

| 步驟 | 結果 |
|---|---|
| preflight | ok=true（Route B 封存後不再 NG） |
| 角色候選 2 張（新提示詞） | 5.5–6.0 秒／張；全身、白底 |
| 頁面候選 2 張（廚房、只畫道具的草圖） | 7.8–13.4 秒／張 |
| 第一次 GET /qa（含線稿渲染，2551×3579） | 0.69 秒；65 個缺口 → errors=["gaps"] |
| 未確認角色就通過 | 409「請先確認角色外型與設定一致」 |
| 有缺口時通過 | 409，列出 gaps 錯誤 |
| 自動補線 | 1.22 秒，加 68 筆，缺口 65 → 0 |
| 手動加一筆 + 通過 | passed |
| 匯出 PDF | 1 頁，MediaBox 612.24 × 858.96 pt（A4＋出血），37 KB |
| print.png | 2551×3579、1-bit、300 DPI |
| 改成 A5 | 線稿 1819×2551；缺口偵測以像素計，縮小後出現 19 個新缺口 → 自動退回草稿；匯出 409「沒有可匯出的頁面」（符合規則） |

觀察：
- 這張頁面多畫了一個女孩（左側），兔耳超出安全區——正是人工 QA（角色一致、安全區疊圖）要抓的；生成本身的問題不在 Phase 3 範圍。
- 改尺寸後要再跑一次自動補線。
