# Phase 7 實機驗收：佇列依模型分組＋產生所有背景（2026-11-10）

## 設定
- ComfyUI 0.36.0 @ 8188（使用者剛重啟，模型未載入）、RTX 5080；開始前 GPU 使用率 0%、/queue 空。
- 分支 `phase7-grouped-queue`（5072ddd）。獨立後端 8020（scratch storage）＋前端 3020（前端複本），不碰使用者的 dev.sh 與 `storage/app.db`。
- Playwright（chromium、`--disable-gpu`）走完整流程，腳本 `accept_run.mjs`；截圖、結果 JSON 在 `processed/`（不進版控）。
- 流程：建書（A4／家用印表機）＋角色 → **先寫好三頁場景描述** → 「產生所有背景」→ 確認 → 等三張背景 → 每頁依序：選背景 → 精準動作 → 合成 → 線稿＋自動補線 → QA 通過 → 390 寬檢查 → 匯出 PDF。
- 場景與動作與 phase6 驗收相同（park／揮手、kitchen／拿著東西、beach／跳起來），方便比較。

## 結果

| 步驟 | Phase 7 | Phase 6（逐頁「背景→動作」） |
|---|---|---|
| 確認框 | 「會為 3 頁產生背景」→ toast「已排入 3 頁背景」 | — |
| 背景引擎時間 | 19.5 s（第一張，含載入 SDXL 背景模型）、**5.4 s、5.7 s** | 20.1、30.1、26.5 s（每張都換模型） |
| 三張背景全部完成 | 33.1 s | — |
| 精準動作引擎時間 | 33.6、33.8、26.4 s | 29.4–30.8 s |
| 每頁（選背景→通過） | 48.5、45.0、39.4 s | 78.0、74.1、69.3 s（含背景） |
| **三頁合計（按下產生所有背景→第 3 頁通過）** | **166.0 s** | **221.4 s** |

- 合計快約 25%（55 s）。整本只換一次模型（SDXL 背景 → Qwen 動作）；背景從每張 18–30 s 回到 5–6 s。
- 動作仍約 26–34 s：Qwen 動作本身就要這麼久（含文字編碼器搬進 VRAM，見 phase7_qwen_background spike）。
- 缺口 127／33／61 → 自動補線後皆 0；三頁都通過；第 1、2 頁仍有「太多過小的區域」警告（SDXL 背景偏繁複，與 phase6 相同）。
- 精準為預設；合成位置（第 2 頁右移 10%＋放大、第 3 頁左移 10%）與畫面一致。
- 390 寬：合成／線稿／QA 水平溢出 0 px。PDF 3 頁匯出成功（`%PDF`，149 KB）。

## 過程中的問題
- 第一次執行中止：腳本在「新增頁面」後立刻輸入場景描述，新頁還沒成為目前頁，文字打進上一頁欄位、切頁時遺失 → 第 2、3 頁沒有場景描述，確認框正確顯示「2 頁略過：沒有場景描述」。
  已用假後端重現，屬腳本競態（真人不會在新頁出現前 100 ms 內打字）；腳本改為等新頁 `aria-current` 後再輸入，重跑通過。產品程式未改。
- 觀察（未修）：剛打完場景描述就按「產生所有背景」時，確認框的頁數可能晚一個存檔來回才更新；實際排入以後端結果為準（toast 顯示真實數字）。

## 結論
「先寫好所有場景 → 產生所有背景 → 逐頁做精準動作」能把整本的換模型次數降到一次，三頁從約 221 s 降到 166 s。若背景也改用 Qwen（見 `phase7_qwen_background_20261110_1104`、設計 `docs/superpowers/specs/2026-11-10-qwen-background-design.md`），背景線稿會更乾淨，且整本不用換模型家族。
