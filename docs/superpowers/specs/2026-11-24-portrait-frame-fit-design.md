# 肖像模式（放進框裡）與華麗相框 v2：設計

日期：2026-11-24　狀態：草稿（已過 builder check），等使用者確認
接在 `2026-11-24-theme-pack-frames-design.md` 之後（同一分支 `frames-pack-2026-11-24`，相框包尚未合併）。

## 1. 為什麼

使用者看了華麗相框的第一版，傳來一張迪士尼公主肖像（貝兒在橢圓框裡，只畫到胸口、塞滿框），
問「人物部分可以像迪士尼這樣的構圖嗎」。也就是：主角放大成半身肖像，下半身和兩側被框的內緣切掉，看起來像掛在牆上的肖像畫。
只借這種構圖，主角仍是使用者自己的角色；那張圖不進流程。

## 2. 使用者的決定（2026-11-24）

| 題目 | 決定 |
|---|---|
| 做法 | A：新增功能（不是只把主角放大、也不是半身不裁） |
| 怎麼開啟 | 構圖舞台加「放進框裡（肖像）」按鈕；華麗相框包每頁預設開啟；其他主題包不受影響 |
| 肖像開著時 | 自動放好之後**還能拖曳、縮放微調**，框外照樣裁掉 |
| 不穩的框 | 星星、愛心、雲朵（約一半機會多包一圈方框或多出東西）換成**空心四葉草（帶方框也可以）、六角形、圓角方形** |
| 草圖 | https://claude.ai/artifact/UTGEvemTWYbErYGe7sGuVh （三個畫面：一般／按下之後／找不到框）。
  草圖裡肖像開著時位置與大小按鈕是停用的；微調指拖曳、拉圓點、方向鍵與 ＋／－ |

## 3. 試做得到的事實（`experiments/results/frames_pack_acceptance_20261124/`）

- **Qwen 不會畫半身**：角色動作指令加 "Half body portrait from the waist up…"，4 個動作都還是全身
  （`halfbody_spike_fullbody_fit.png`）。動作範本寫死的 "Full body" 不改。
- **找框的內圈很可靠**：背景灰階 < 160 當線條、5×5 膨脹補小缺口、4 連通找「種子點所在的白色區域」，
  12 張相框背景的內圈都找對（`interior_detect_r4.png`）。
- **全身角色放大＋裁進內圈＝肖像**：角色高度＝內圈高 × 0.92 ÷ 0.62（框裡看得到上面約 62%），
  頭頂在內圈頂端往下 8% 內圈高，水平置中於內圈；超出內圈的部分（腿、兩側）裁掉
  （`halfbody_spike_portrait.png`，使用者看過）。不需要額外 GPU，已經做好的角色動作也能直接用。
- 只看得到胸口以上，所以肖像頁的動作要是上半身動作（揮手、比愛心、托臉頰、捧東西）。

## 4. 目標、非目標、反目標

**目標**
- 任何有框的背景，按一下就變成肖像；再按一次回到一般擺放。
- 肖像開著仍可拖曳、縮放；舞台上看到的裁切結果與合成、列印一致。
- 華麗相框包一鍵做書時，每頁自動是肖像，不用使用者動手；換背景（再產生一張）後自動重新對齊新框。
- 合成是確定性的（同背景＋同角色動作＋同位置 → 同一張圖），沿用合成圖重用機制。

**非目標**
- 讓 Qwen 生成半身角色、改角色動作範本。
- 其他主題包預設開肖像；在角色動作卡片加「全身／半身」選項。
- 一頁多個框、使用者自己畫框的範圍。

**反目標**
- 沒有開肖像的頁面，合成結果與今天**逐像素相同**（現有書不能變）。
- 找不到框時不可裁出奇怪的形狀：要清楚說「這張背景找不到框，照一般擺放」，並回到一般擺放。
- 不新增 GPU 工作、不新增佇列服務；找框在後端用 numpy/OpenCV 做，跟合成一樣。

## 5. 設計

### 5.1 位置資料（Placement）多兩個選填欄位

- `frame`: `null` 或 `{x, y}`（0–1）。不是 null ＝肖像：以背景上的這一點當種子找內圈，合成時把角色裁進內圈。
  按下按鈕時存的是當時找到內圈用的種子點，之後拖曳不會改它（所以裁切範圍不會因為拖曳跳到別的區域）。
- `autofit`: bool，預設 false。true ＝合成時依內圈重新算 cx、cy、height（§5.3）；任何手動調整（拖曳、縮放、鍵盤、
  按位置／大小鈕）都送 `autofit: false`。按鈕打開的肖像也是 `autofit: true`（換背景會跟著新框重新對齊，直到手動調整；我的判斷）。
- 高度上限：`frame` 不是 null 時 `height` 可到 **2.0**（肖像常要比整頁高，框外會裁掉）；沒開肖像仍是 0.1–1.0。
  後端 `validate()` 與前端 `clampPlacement`／縮放都依 `frame` 決定上限（我的判斷）。
- 兩個欄位都沒有＝今天的行為。後端 `Placement.from_dict`／`to_dict`／`key()`、前端 `Placement` 型別與
  `clampPlacement` 都要帶上；`key()` 包含它們，舊位置的 key 不變（沒有這兩欄時與今天相同），所以現有合成圖照常重用。
- `COMPOSE_VERSION` 不必改（沒開肖像的輸出不變）；肖像合成圖的 params 會記錄 `frame` 與 `autofit`。

### 5.2 找內圈（後端純函式，新檔 `backend/app/services/frame_fit.py`）

- `find_interior(background: Image, seed: (x, y)) -> np.ndarray | None`：§3 的演算法（門檻、膨脹大小、連通性寫成具名常數，
  膨脹大小隨背景尺寸縮放）。種子點剛好落在線條上時，往外找最近的白色像素（小範圍）。
  找到的白色區域要**補洞**（被區域完全包住的線條與小東西算在內圈裡，例如框裡多畫的一隻熊），角色會蓋住它們；
  碰到框邊的雜物（例如連到框的山丘線）不處理，那張背景請使用者重畫（相框包的場景本來就要求框裡乾淨；我的判斷）。
- **算不算框**：區域面積在整張的 5%–75% 之間，而且碰到的紙張邊不超過一邊（拱門的內圈會碰到下緣，要算框）。
  否則回 None。門檻用相框包驗收的 12 張和幾張一般場景背景（公園、教室）校正，寫成測試。
- `fit_portrait(interior, pose_cutout_size, background_size) -> (cx, cy, height)`：§3 的公式，常數具名。
- 預設種子點 `(0.5, 0.55)`。

### 5.3 合成（`compose()`／`compose_page`）

- `frame` 不是 null 時：先找內圈；找不到 → 這張照一般合成（不裁、用頁面存的 cx、cy、height，但 height 超過 1.0 時夾到 1.0），
  **頁面位置的 `frame`、`autofit` 保留**（換下一張背景會再試；我的判斷）；存的 height 大於 1.0 時寫回 1.0（否則頁面位置永遠對不上合成圖，編輯頁一直顯示「待更新」；最終審查 2026-11-24）。一鍵流程（`?oneclick` 與整本自動做）合成時找不到框，
  這頁標「請看一下」，原因「這張背景找不到框，照一般擺放，可以再畫一張背景」（沿用現有 attention 機制；我的判斷）。
  找到：`autofit` 為 true 就先用 `fit_portrait` 算出 cx、cy、height 並寫回頁面位置（`autofit` 保持 true）；然後照今天的方式縮放、翻轉、貼上，只是貼上的遮罩再乘上內圈遮罩
  （內圈不膨脹，框線會蓋在角色上，切口藏在框線底下）。
- 寫回位置是同一個交易裡直接更新 `placement_json`：寫回的是程式算出的數字，不是使用者改了位置，所以不存復原快照、不清 `pending_user_strokes`（實作時決定，2026-11-24）。
- 補線、QA、匯出都吃合成圖，不用改。

### 5.4 API

- `POST /api/pages/{page_id}/frame-fit`：用這頁選定的背景與角色動作，找內圈（種子 `(0.5, 0.55)`）並算肖像位置；
  回 `{cx, cy, height, flip（保留頁面現值）, frame: {x, y}, autofit: true}`，**不存檔**（前端拿到後走現有存位置＋自動合成）。
  找不到框 → 422「這張背景找不到框，照一般擺放」。缺背景或角色動作 → 沿用現有錯誤。
- `GET /api/generations/{gen_id}/frame-mask?x=&y=`：背景的內圈遮罩 PNG（與背景同尺寸，白＝內圈），給舞台預覽用；
  權限同現有圖片端點；找不到框 → 404。結果可快取（同一張背景＋同一點不變）。
- `PUT /pages/{id}/placement` 接受新欄位（驗證：`frame` 的 x、y 在 0–1；`autofit` 是 bool）。

### 5.5 前端（`ComposeStage`，編輯頁與一鍵處理頁共用）

照草圖：
- 「水平翻轉」「重設位置」旁加「放進框裡（肖像）」切換鈕（`aria-pressed`）。
  - 關 → 開：呼叫 frame-fit；成功就套用（存位置＋自動合成）；422 就在狀態列顯示「這張背景找不到框，照一般擺放」，按鈕維持沒按。
  - 開 → 關：位置回到預設（保留翻轉），`frame`、`autofit` 清掉。
- 肖像開著但這張背景找不到框（frame-mask 404）：狀態列顯示「這張背景找不到框，照一般擺放」，按鈕保持按下（換背景會再試）。
- 肖像開著：位置、大小快捷鈕停用；拖曳、拉圓點、方向鍵、＋／－ 照常（都會送 `autofit: false`）。
  說明文字換成「肖像：主角自動放大，框外的部分裁掉。可以拖曳或拉圓點微調；再按一次『放進框裡』關掉。」
- **預覽要裁**：肖像開著時，角色圖層套上 frame-mask（CSS mask，與舞台同大小對齊），拖曳中也看得到裁切結果；
  圓點把手與焦點框不被裁掉。遮罩載入失敗就不裁（狀態列不用報錯）。
- 「重設位置」在肖像開著時：等同關掉肖像。

## 6. 驗收

- 單元測試：找內圈（相框背景找到、一般場景回 None、拱門算框、種子在線上、框裡的小東西被補洞）、肖像高度 >1.0 只在 frame 時允許、
  換背景找不到框時 frame／autofit 保留、一鍵流程找不到框標「請看一下」、fit 公式、沒開肖像時合成逐像素不變、
  肖像合成只在內圈裡有角色像素、autofit 寫回、frame-fit／frame-mask 端點（含 422／404）、Placement 新欄位驗證。
- 前端測試：切換鈕開／關、找不到框訊息、肖像時快捷鈕停用、手動調整送 autofit false、遮罩套用。
- GPU 驗收（雪花小女孩）：先三個新形狀各畫兩次確認乾淨；再用相框包做一整本，縮圖總表給使用者；
  再在瀏覽器走一次：編輯頁按「放進框裡」→ 拖曳微調 → 關掉，以及一般場景頁按下時的找不到框訊息（截圖給使用者）。
