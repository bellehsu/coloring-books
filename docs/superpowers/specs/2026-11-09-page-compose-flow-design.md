# 頁面合成流程：背景與角色分開生成，再合成（設計文件）

日期：2026-11-09
狀態：已納入使用者 2026-11-09 的決定與 builder check，待使用者確認
相關：`docs/superpowers/specs/2026-11-06-coloring-book-web-design.md`（原設計，本文件修改其 §6.3 頁面編輯器與 §10 生成設定）、
`experiments/results/phase5_compose_spike_20261109/NOTES.md`（可行性實驗）、`CLAUDE.md`

## 1. 為什麼要改

使用者實際用 Phase 4 的頁面編輯器後回報三個問題：

1. **場景描述效果差**：同一次生成同時帶角色參考圖（IP-Adapter）與場景描述，角色主導畫面，場景幾乎被忽略
   （Phase 4 實測：寫「in a cozy kitchen」卻沒畫出廚房）。
2. **畫構圖會改到角色**：構圖草圖（ControlNet）和角色一起生成，畫的線條會扭曲角色外型。
3. **不需要一次 4 張**：背景一次產生一張就好，不滿意再產生。

可行性實驗（2026-11-09）證實：背景**不帶角色參考圖**時，場景描述與構圖都能被正確遵守；
角色在**白底**單獨生成時，可以依動作文字畫出不同姿勢，外型大致一致；去背後貼進背景，轉成線稿後看不出接縫。

## 2. 新流程（使用者確認）

每一頁分成三個生成步驟，之後接原本的線稿、修線、QA、匯出：

1. **背景**：寫場景描述，可選擇在畫板畫構圖（選用）。按一次產生**一張**不含角色的背景。
2. **角色**：寫動作描述，或點選常用動作按鈕帶入。按一次產生**一張**白底的角色新動作，系統自動去背。
   AI 依這一頁的情境畫出不同動作（使用者選的方式），不是直接貼角色工作室那張原圖。
3. **合成**：在背景上拖拉角色的位置與大小，可以水平翻轉，確認後產生合成彩圖。
4. 合成彩圖進入原本的「線稿與修線 → QA → 匯出」，這部分不變。

背景與角色動作各自保留歷史，可以換回舊的。

## 3. 目標、非目標、反目標

**目標**
- 場景描述與構圖草圖只影響背景，不再影響角色外型。
- 角色外型在每一頁一致（以本書角色參考圖為準），動作依每一頁的描述改變。
- 背景、角色每次各產生一張，速度快（實測約 6 秒／張）。
- 合成後的頁面沿用 Phase 3／4 的線稿、修線、自動補線、QA、匯出，不需重做。

**非目標（這一版不做）**
- 一頁放多個角色或同一角色出現多次（作者決定：一頁一個主角）。
- 火柴人／姿勢編輯器（使用者選了「文字＋常用動作按鈕」）。
- 讓 AI 把角色「畫進」背景（局部重繪）；角色與場景物件精準互動（例如真的坐在背景的鞦韆上）。使用者已接受這個限制。
- 自動陰影、透視或光線調整（著色本是線稿，不需要）。
- 把舊的「一次生成角色＋場景」頁面轉成新流程。

**反目標（做到也算失敗）**
- 換背景或換角色動作後，畫面還留著舊的合成結果卻被當成目前的頁面送去匯出。
- 角色外型偏離設定卻沒被發現（QA 的人工角色檢查必須保留）。
- 使用者大部分時間在等機器（一次一張就是為了避免這點）。

## 4. 限制（CLAUDE.md，必須遵守）

- 單一 GPU、FastAPI 內單一背景 worker；不引入 Redis／Celery。
- Workflow 模組化（`workflow_api.json` + `manifest.yaml`），manifest 白名單參數，節點以 `_meta.title` 定位；
  新節點與輸入要用執行中 ComfyUI 的 `/object_info` 驗證，不可猜。
- 頁面與生成紀錄分離：page 只存選定的 generation id；重新生成只新增 generation。
- 每筆 generation 保存 workflow 名稱與版本（hash）、模型檔名、所有參數、seed、提示詞、耗時、錯誤訊息。
- 路徑只來自 `config/settings.yaml`（可用 `APP_` 環境變數覆寫）。
- 不自行下載模型：去背用的 `background_removal/birefnet.safetensors` 已在 `comfy.models_root`，要列入 manifest 的模型清單讓 preflight 檢查。
- 每個模組都有測試；ComfyUI 相關測試可用 mock 執行。
- 資料表變更要有 Alembic migration。

## 5. 各步驟的行為

### 5.1 背景
- 輸入：場景描述（0–800 字）、選用的構圖草圖（沿用 Phase 4 的點陣畫板，只影響背景）、構圖強度（沿用 0–0.6）。
- 生成：SDXL Base，**不使用 IP-Adapter**；有草圖時用 ControlNet Union scribble（沿用現有設定），沒有草圖時純文字生圖。
  尺寸＝繪本的生成尺寸（`compute_layout(...).generation_size`）。
- 提示詞：場景描述＋著色本風格＋「簡單、物件少、不要有人物」；負向提示詞壓制人物與動物。
  實驗顯示純文字背景太繁複（一頁 60–84 個缺口），提示詞要加「簡單、物件少」並在實作時用 GPU 校正（見 §8）。
- 一次一張；歷史保留，可選回舊的背景。

### 5.2 角色動作
- 輸入：動作描述（文字），以及一排常用動作按鈕，點了會把對應的英文片語帶入描述。
  **不帶入這一頁的場景描述**（使用者決定）：避免角色圖自己畫出場景物件、貼進背景時重複；需要拿東西就寫在動作裡。
  因此改場景描述不會讓角色動作過期。
  預設按鈕（作者決定，之後可調）：站著、坐著、走路、跑步、揮手、指向前方、拿著東西、跳起來、看書、開心笑。
- 生成：SDXL Base＋IP-Adapter（本書角色參考圖），白底；**IP-Adapter weight 0.55、end_at 0.6**
  （實驗：0.8 會無視動作照抄參考圖站姿）。不使用構圖草圖。
  提示詞：角色描述＋動作＋全身＋著色本風格＋白底（沿用角色工作室的白底寫法）。
- 去背：ComfyUI 內建 `LoadBackgroundRemovalModel`（`birefnet.safetensors`）＋ `RemoveBackground`，產生遮罩。
  遮罩與角色圖都要存檔並記在 generation 上。
- 一次一張；歷史保留，可選回舊的角色動作。**歷史每一頁各自保存**（使用者決定），不做整本共用的動作庫。

### 5.3 合成
- 在背景預覽上顯示去背後的角色，可拖拉位置、拖拉角落縮放、水平翻轉、重設。
  預設：水平置中、貼近下方、高度約為畫面的六成（作者決定）。
- 位置以相對座標保存（不受解析度影響）；「確認合成」時由後端用確定性的影像處理（不經 GPU）產生合成彩圖。
- 合成彩圖成為這一頁的選定圖片，後面的線稿、修線、QA、匯出照舊。
- **選了不同的背景或角色動作（還沒確認合成）時**：頁面的選定圖片立即清空、退回草稿（作者決定），
  線稿／QA 分頁停用並提示「請重新確認合成」；這樣匯出與單頁 PNG 不可能輸出舊的合成圖。
- **合成歷史與沿用**（作者決定）：確認合成時，若背景、角色動作、位置都和某一張既有合成圖相同，就直接選回那張，
  它的修線也一起回來；否則產生新的合成圖（舊合成圖上的修線不帶過去，因為位置已不同），頁面退回草稿。
- **位置草稿存在後端**（作者決定）：拖拉時前端即時預覽，停手後自動存（依序送出，沿用 Phase 4 的寫入佇列做法），
  重新整理或切換分頁不會遺失；只有按「確認合成」才產生合成圖。

### 5.4 頁面編輯器的變化
- 中間的模式分頁改成：**背景 → 角色 → 合成 → 線稿與修線 → QA 檢查**。
  前一步沒完成時，後面的分頁停用並說明原因（沿用 Phase 4 的做法）。
- 「本頁進度」清單改成：背景、角色動作、合成、線條封閉、角色外型、通過 QA。
- 原本的候選圖托盤改成「背景歷史」與「角色動作歷史」，各自顯示在對應的分頁。
- 角色工作室（建立本書角色）不變，仍然一次 4 張讓使用者挑。

## 6. 資料與 API（建議，實作者可調整，但要守 §4）

作者建議的做法（實作者可以換更好的做法，但要說明理由）：

- `Generation.kind` 新增 `background`、`pose`、`composite`。
  - `pose` 的 generation 另外保存去背遮罩的路徑。
  - `composite` 不經 GPU，由後端合成；仍寫一筆 generation，`engine`／`workflow_name` 記為後端合成程式與版本，
    `params` 記背景 id、角色動作 id、位置（中心 x、y、高度比例、是否翻轉），以滿足「每筆 generation 都要能追溯」。
  - 頁面的 `selected_generation_id` 指向目前的 `composite`，這樣線稿、修線圖層（以 generation 為 key）、QA、匯出都不用改。
- 頁面新增：目前選用的背景 id、目前選用的角色動作 id、目前的位置（尚未確認合成時的草稿）。
- 新 API（名稱由實作者定）：
  - 產生背景（`count` 固定 1）、選用背景；
  - 產生角色動作（`count` 固定 1，帶動作文字）、選用角色動作；
  - 儲存位置、確認合成（產生 `composite` 並設為選定圖片）。
- 新 workflow：背景用的（不含 IP-Adapter，ControlNet 可關）；角色動作用的（含 IP-Adapter 與去背節點，輸出角色圖與遮罩兩張）。
  ComfyUI 引擎目前一次只回傳一張圖，要擴充成可以回傳多個輸出。
- 舊的 `POST /api/pages/{id}/candidates`（角色＋場景一起生成）不再出現在介面；API 是否保留由實作者決定。
- **舊流程的頁面**（作者決定）：打開時同樣顯示新的五個分頁（背景／角色／合成為空）。原本選定的 `page` 圖片保持選定，
  照常可以看線稿、QA、匯出，直到使用者確認新的合成圖取代它；舊的候選圖托盤從介面移除。

## 7. 成功標準

- 公園、廚房、房間三個場景：背景照場景描述畫出主要物件；有構圖草圖時照草圖擺放。
- 同一本書 5 頁不同動作：人工檢查角色外型與參考圖一致（耳朵、髮型、衣服顏色）。
- 從開新頁到合成完成，扣掉等待時間，操作步數不多於 Phase 4（一頁通過仍在 5–10 分鐘內）。
- 合成線稿用自動補線後缺口歸零的比例，不低於 Phase 3 校正時（26/27 頁）。

## 8. 交給實作者決定的事

- 背景「簡單、物件少」提示詞的確切寫法與 ControlNet 強度，用 GPU 對三個場景實測後決定，結果寫進 `experiments/results/`。
- 常用動作按鈕的英文片語。
- 合成時角色邊緣的處理（遮罩羽化幾 px）。
- 角色動作圖的尺寸（實驗用 832×1216）。
- 資料表欄位與 API 路徑的確切名稱。

## 9. 作者自行決定的事（請確認）

- 一頁只放一個主角。
- 背景與角色動作都是一次一張；角色工作室維持一次 4 張。
- 角色動作的 IP-Adapter 權重 0.55／end 0.6（依實驗）。
- 合成預設位置：水平置中、貼近下方、高度六成；可水平翻轉。
- 換背景或角色動作後要重新確認合成，舊合成上的修線不帶過去，頁面退回草稿。
- 合成用 `composite` generation 接上既有的線稿／修線／QA／匯出流程。
- 常用動作按鈕預設十個（站、坐、走、跑、揮手、指向、拿東西、跳、看書、開心笑）。
- 舊流程的頁面不轉換；打開時顯示新分頁，原選定圖照常可用到確認新合成為止。
- 選了不同背景／角色動作（未確認合成）時，立即清空選定圖片並退回草稿。
- 確認合成時，背景＋動作＋位置相同就沿用既有合成圖（含修線）。
- 位置草稿存在後端，自動、依序儲存。

## 10. 使用者決定（2026-11-09）

- 背景與角色分開生成、再合成；角色由 AI 依每一頁畫不同動作，再貼進背景（不做局部重繪）。
- 動作輸入：文字＋常用動作按鈕。
- 背景的構圖畫板保留，當作選用。
- 角色動作只用動作文字，不帶入場景描述。
- 角色動作歷史每一頁各自保存。
