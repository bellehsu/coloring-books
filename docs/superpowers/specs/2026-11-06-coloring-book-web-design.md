# 著色繪本製作網站：設計文件

日期：2026-11-06
狀態：草稿（已納入審閱意見與使用者 2026-11-06 的決定），待使用者確認
相關：`CLAUDE.md`（專案規則）、`experiments/results/phase1_route_c*/NOTES.md`（生成與線稿實驗）

## 1. 目的

讓使用者在網頁上完成一整本「固定角色」的兒童著色繪本：先用文字產生並挑定角色，再一頁一頁產生場景、
轉成可塗色的線稿、檢查品質，最後輸出可直接列印的檔案。ComfyUI 只是背後的生成引擎，使用者不需要接觸它。

## 2. 使用者與使用情境

- 第一版只給使用者本人與團隊內部使用，部署在公司內網，不開放外網。
- 目前一本書由一個人從頭做到尾，包括 QA。
- 共用一張 GPU（RTX 5080 16 GB）。
- 同時使用的人數預期很少（1–2 人）。生成佇列採先到先處理；網頁顯示排隊位置與預估時間，使用者可以取消自己還沒開始的任務。
  繪本清單所有人共用（無帳號）。（作者決定）
- 部署：後端、前端、ComfyUI 跑在目前這台 WSL2 工作站。第一版提供「內網存取」的部署步驟（前端正式建置、後端以服務方式啟動、
  Windows 連接埠轉發到 WSL2）。ComfyUI 只綁定本機，不對內網開放。（作者決定）

## 3. 成功標準

- **一個人一天內做出 20 頁可以直接列印的繪本。**（一天約 8 小時，平均每頁 24 分鐘，包含挑圖、修線、QA。）
- 每頁都經過 QA：角色外型與設定一致、線條閉合。

## 4. 目標、非目標、反目標

**目標（第一版功能，使用者勾選）**
1. 用 prompt 產生角色、挑選並設為本書角色
2. 網頁畫板畫構圖（筆刷、直線、方框、圓、橡皮擦）
3. 上傳參考圖當構圖（自動轉成線條給 ControlNet）
4. 候選圖保留／捨棄、重新生成；每頁保留生成紀錄，可換回舊的
5. 線條細緻度、線寬即時調整（不用重新生成）
6. 在線稿上手動修線（擦掉多餘線條、補線）
7. 匯出：使用者可挑尺寸，輸出 PDF
8. 列印方式：家用印表機或印刷廠（使用者 2026-11-06 新增），選擇後自動調整生成與版面（§6.1）

**非目標（第一版不做）**
- 上傳自己的角色圖（使用者沒有選）
- 帳號、權限、付費
- 雲端 GPU。日後若上雲，會改用 diffusers 直接跑模型、不用 ComfyUI；第一版只需讓生成層可以替換（見 §9）
- 自動訓練 LoRA
- 內容過濾（內部使用）
- 多人同時編輯同一頁的衝突處理（以後存的為準）
- 自動判斷角色相似度的模型（第一版人工判斷，見 §7）
- Route A、Route B（使用者決定 Route C 為唯一路線）
- 封面、頁碼、背面留白頁（作者決定第一版不做）

**反目標（做到了也算失敗）**
- 角色外型偏離設定卻沒被發現就印出去
- 線條有缺口、塗色會漏出去的頁面被當成可列印
- 使用者大部分時間在等機器，而不是在挑圖、修線
- 前端或 API 可以改動 manifest 白名單以外的 ComfyUI 節點（違反 CLAUDE.md）

## 5. 限制（來自 CLAUDE.md，必須遵守）

- 後端 Python 3.11+、FastAPI、SQLModel、SQLite；前端 Next.js + React + TypeScript。
- ComfyUI 是獨立服務，以 HTTP/WebSocket API 呼叫，不改它的原始碼。
- 單一 GPU：生成任務由 FastAPI 內**單一背景 worker** 依序執行，狀態存 SQLite；不引入 Redis、Celery 等佇列服務。
- Workflow 模組化（`workflow_api.json` + `manifest.yaml`），後端只接受 manifest 白名單參數，節點以 `_meta.title` 定位。
- 頁面與生成紀錄分離：page 底下有多筆 generation，page 只存 `selected_generation_id`；重新生成只新增 generation。
- 每筆 generation 保存：workflow 名稱與版本（hash）、模型檔名、所有參數、seed、提示詞、耗時、錯誤訊息。
- 路徑只來自 `config/settings.yaml`（可用 `APP_` 環境變數覆寫）。
- 每個模組都要有測試；ComfyUI 相關測試要能用 mock 跑。
- 不自行下載模型；需要新模型時列出來源讓使用者下載。

## 6. 使用流程（使用者確認）

### 6.1 我的繪本
- 繪本清單、建立新繪本。
- **建立時選紙張尺寸與列印方式**（使用者確認：尺寸在建立繪本時決定；列印方式 2026-11-06 新增）。兩者決定內容範圍與生成尺寸；之後可在繪本設定中修改（規則見下方）。

| 紙張尺寸 | 公分 | 300 DPI 像素（整張紙） | 比例群組 |
|---|---|---|---|
| A4 | 21 × 29.7 | 2480 × 3508 | 直式 ISO（≈0.707） |
| A5 | 14.8 × 21 | 1748 × 2480 | 直式 ISO |
| B5（JIS） | 18.2 × 25.7 | 2150 × 3035 | 直式 ISO |
| US Letter | 21.6 × 27.9 | 2550 × 3300 | Letter（0.773） |
| 正方形 | 21 × 21 | 2480 × 2480 | 正方形（1.0） |

生成尺寸與目標比例不完全相同時，後處理以 `fit: contain` 補白邊（不裁切，避免切到角色）。

**列印方式（使用者決定：建立繪本時選，並自動修正生成）**

| 列印方式 | 版面 | 內容範圍（線稿畫在哪裡） | PDF 頁面大小 |
|---|---|---|---|
| 家用／辦公室印表機 | 四邊各留 10 mm 白邊（印表機印不到邊緣） | 紙張減去白邊，例如 A4 → 190 × 277 mm（2244 × 3272 px） | 紙張大小 |
| 印刷廠 | 四邊各加 3 mm 出血；裁切線內再留 5 mm 安全區 | 含出血的整個範圍，例如 A4 → 216 × 303 mm（2551 × 3579 px）；角色與重要線條要在安全區內 | 紙張＋出血 |

「自動修正生成」的意思：
- 生成尺寸依「內容範圍」的比例，從固定清單 1024×1024、896×1152、864×1216、832×1216、768×1344（約 1 MP，皆為 32 的倍數）選比例最接近的。例如 A4 家用 0.686 → 832 × 1216；
  A4 印刷廠 0.713 → 864 × 1216；Letter 家用 0.755 → 896 × 1152；正方形 → 1024 × 1024。
- 線稿後處理的目標尺寸＝內容範圍的 300 DPI 像素。
- 畫板顯示對應的參考線：家用顯示白邊；印刷廠顯示出血線、裁切線、安全區。畫板與上傳的參考圖都以內容範圍的比例呈現。
- 自動 QA 加一項：印刷廠模式下，在線稿上疊出裁切線與安全區，讓使用者確認角色沒有超出安全區（人工確認）。
- 著色頁大多是白底，出血區通常只有背景線條；生成時不需要特別處理出血。
- 第一版不加裁切標記（crop marks）。（作者決定）

**換尺寸的規則（作者決定）**：繪本建立時選定一個具體尺寸（例如 A4），所有線稿、QA、匯出都以這個尺寸的 300 DPI 為準。
之後可在繪本設定中改成同比例群組的其他尺寸，或改列印方式；改了之後：
- 線稿依新尺寸重新擷取，**線條在紙上的粗細維持不變**（線寬以 mm 為準，換算成該尺寸的 px）；
- 手動修改圖層以「相對座標」（0–1）儲存，所以可以跟著換算；
- 自動 QA 全部重算，原本「通過」的頁面若新結果有錯，退回草稿。
- 若新的內容範圍比例對應到不同的生成尺寸，既有圖片不重新生成，以補白邊放入新範圍，並在頁面上提示「比例不同，建議重新生成」。
匯出一律使用繪本目前的尺寸，不在匯出時另選。

### 6.2 角色工作室
1. 輸入角色描述，按「產生 4 張」。
2. 候選逐張保留／捨棄；可再產生。
3. 選定一張後並排顯示彩色原圖與線稿預覽。
4. 「設為本書角色」：這張彩色圖成為本書所有頁面的 IP-Adapter 參考圖，角色描述成為每頁提示詞的一部分。
5. 角色設定後原則上不再更換（換角色＝新書）。

### 6.3 頁面編輯器（主要工作畫面）
> 2026-11-09 更新：頁面改為「背景 → 角色動作 → 合成」流程，每次只產生一張，取代下面的整頁 4 張候選；見 `2026-11-09-page-compose-flow-design.md`。

- 左：頁面清單（縮圖、狀態），可新增、排序。
- 中：畫板。只畫背景與道具，**角色位置留白**（實驗 C2／C3：畫火柴人會把角色比例拉壞；只畫道具時角色正常）。
  工具：筆刷、直線、方框、圓、橡皮擦、清除、上傳參考圖。上傳的參考圖用 xdog 轉成白底黑線後放進畫板，可再編輯。
  畫板空白時不使用 ControlNet（強度 0）。
- 右：場景描述、構圖強度、線條細緻度、線寬、「產生候選」。
- 下：候選圖（每次 4 張），保留／捨棄；選定的那張成為本頁的 `selected_generation_id`。
- 線條參數改變時只重新擷取線稿（約 1 秒），不重新生成。
- 手動修線：在線稿上擦除、補線（見 §8）。

### 6.5 匯出
- 以繪本目前的尺寸與列印方式輸出整本 PDF（每頁一張 1-bit 線稿，300 DPI；家用＝紙張大小含白邊，印刷廠＝紙張＋出血）；也可下載單頁 PNG。
- 預設只匯出「通過」的頁面；有未通過的頁面時提醒。

## 7. QA

使用者在意兩件事：**角色外型是否和設定不同**、**線條閉合度**。

1. **線條閉合度（自動）**
   - 新增指標：懸空線頭數（骨架上只有一個鄰居的端點）與小缺口數（兩個線頭距離小於 N px）。
   - 在線稿上以紅點標出位置。超過門檻時頁面標成「需要修線」。
   - 用手動修線工具補起來後自動重算。
   - 既有指標一併顯示為警告：黑填充比例（大片黑塊）、過小區域數（塗不進去）、碎片數。
2. **角色外型（人工）**
   - QA 畫面把本書角色參考圖與本頁彩圖、線稿並排，使用者點「一致／不一致」並可加註記。
3. **頁面狀態**：草稿 → 通過。自動檢查有錯誤時不能標成通過（可強制通過，需填原因）。

## 8. 線稿與手動修線

- 擷取：xdog（`app.services.lineart_extract`），再經 `lineart_post` 後處理（放大、清碎片、閉運算、統一線寬、1-bit）。
- 細緻度三檔（使用者接受 sigma 1.2 為「標準」）：簡單＝xdog sigma 1.5、標準＝1.2、細緻＝0.8。線寬滑桿 8–16 px（預設 11）。
- 手動修線存成**獨立的修改圖層**（補線筆畫、擦除筆畫，以目標解析度座標記錄），每次重新擷取後再疊上去，
  所以調參數不會讓修改消失。參數改變導致線條位置大幅變動時，使用者需重修。
- 已知限制：衣服條紋等「模型畫出來的圖樣」無法用擷取參數單獨去除（見 C4 NOTES）；要簡化須改角色設定。

## 9. 架構

```
瀏覽器（Next.js：繪本、角色工作室、頁面編輯器＋畫板、QA、匯出）
   │ HTTP / WebSocket（進度）
FastAPI 後端
   ├─ 資料：SQLite（books / pages / generations / …）、storage/（圖片、畫板、修改圖層、PDF）
   ├─ 生成佇列：單一背景 worker
   ├─ 生成引擎介面 ── 第一版：ComfyUI 引擎（manifest 白名單 → 節點）
   │                   日後：diffusers 引擎（同一組邏輯參數）
   ├─ 線稿服務：lineart_extract + lineart_post + 修改圖層
   ├─ QA 服務：閉合度與其他指標
   └─ 匯出服務：PDF
ComfyUI（本機獨立服務）
```

- 網頁與後端只使用「邏輯參數」（prompt、角色參考圖、構圖圖、seed、強度、尺寸…），不碰 ComfyUI 節點。
- 生成紀錄的「版本」：ComfyUI 引擎記 workflow hash；日後的 diffusers 引擎記其設定的 hash。

## 10. 生成設定（實驗結論，作為預設）

來源：`experiments/results/phase1_route_c3_*`、`phase1_route_c3_final_compare_*`、`phase1_route_c4_age_*`。

- 頁面生成（Route C）：SDXL Base 1.0 + IP-Adapter Plus（weight 0.55、end_at 0.6）+ ControlNet Union scribble（0.4、end 0.5）。
  提示詞：`{角色描述}, {場景描述}, children's picture book illustration, flat colors, thick clean black outlines, simple shapes, full detailed background scene`；
  負向：`plain background, empty background, white background, photo, realistic, 3d render, gradient, soft shading, airbrush, texture, noise, blurry, sketch, monochrome, grayscale, text, watermark, signature`。
- 現有 workflow `route_a_sdxl_ipadapter_cn` 已支援上述參數；寬高參數依 §6.1 的生成尺寸規則設定。
  （這個 workflow 名稱帶有 route_a，是歷史原因；Route C 沿用它。實作者可決定是否改名為 Route C 的 workflow，改名會改變版本 hash。）
- 角色工作室需要一個**新的純文生圖 workflow**（SDXL，無 IP-Adapter／ControlNet），提示詞同上但加白底、全身、正面。
- 年齡提示詞（C4）不採用（使用者決定）。
- **Route C 為唯一生成路線**（使用者 2026-11-06 決定）。Route B（Qwen-Image-Edit）不再比較，`route_b_qwen_edit_2511_gguf` manifest 保留但不使用。
  CLAUDE.md 的「兩條生成路線（Phase 1 要比較）」段落需改寫成 Route C（由使用者修改或同意後修改）。

## 11. 階段

CLAUDE.md 規定依 Phase 順序、每個 Phase 結束停下來確認。以下對應是作者的判斷：

- **Phase 1 完成**：Route C 為唯一路線（已完成實驗 C0–C4，使用者決定不比較 Route B）。
- **Phase 2 後端核心**：資料模型、生成引擎介面＋ComfyUI 引擎、單一 worker 佇列、繪本／角色／頁面／生成 API、角色用文生圖 workflow。
- **Phase 3 線稿、QA、匯出**：線稿 API（即時重擷取）、修改圖層、閉合度指標與標記、頁面狀態、版面參考線與 PDF 匯出。
  （紙張尺寸、列印方式與生成尺寸的計算在 Phase 2 就需要，因為生成要用到。）
- **Phase 4 前端**：四個畫面與畫板。

## 14. 作者自行決定的事（請確認）

- 每次產生 4 張候選。
- 角色設定後不更換（換角色＝新書）。
- 手動修線用獨立修改圖層。
- 生成尺寸與目標比例不同時補白邊、不裁切。
- 細緻度三檔對應 xdog sigma 1.5／1.2／0.8，線寬 8–16 px（以 A4 300 DPI 為準，換尺寸時依紙上粗細換算）。
- 繪本建立時選定具體尺寸；改尺寸會重新擷取線稿、換算修改圖層、重跑 QA；匯出一律用繪本目前尺寸。
- 生成佇列先到先處理、可取消；部署在這台 WSL2 工作站並提供內網存取步驟，ComfyUI 只綁本機。
- 畫板空白時 ControlNet 強度為 0；上傳的參考圖先轉線稿再進畫板。
- 頁面狀態只有「草稿／通過」，自動檢查有錯不能直接通過（可強制並填原因）。
- 匯出預設只含通過的頁面。
- Phase 2–4 的切法。
- 家用白邊 10 mm；印刷廠出血 3 mm、安全區 5 mm；第一版不做裁切標記、封面、頁碼。
- 改列印方式或尺寸後若生成比例不同，不自動重新生成，只補白邊並提示。
